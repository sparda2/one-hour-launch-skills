# The proven sales-page structure (distilled from the reference pages)

This is the skeleton every generated page follows. It's reverse-engineered from a long-form, no-VSL sales page that is actively scaling (the "peptides" reference), cross-checked against the user's own page. Keep the ORDER; adapt the content to the product. A section may be dropped only if the product genuinely has no honest material for it — never fill it with invented proof.

## Section order (top → bottom)

1. **Announcement bar (sticky).** One line: the core promise or the launch framing. Optional honest deadline (see integrity rules).
2. **Hero.** Big specific headline (the outcome, tonight/this week, concrete), one-line subhead, the product mockup image, 3 trust chips (e.g. "instant access · one-time payment · <real> guarantee"), primary CTA. No price in the hero.
3. **Mechanism / "how it works".** The product shown as a system in 3 steps, each with a sub-image. Turns a PDF/app into a "machine that produces the outcome".
4. **The uncomfortable truth / problem agitation.** Name the reader's current painful situation in their own words (scattered info, trial and error, wasted money). Mirrors the ad's hook.
5. **What you achieve / outcome bullets.** The after-state, benefit-led, specific. Pairs each pain from §4 with its resolution.
6. **What's inside (deliverables).** Every module/asset with a one-line value statement and a thumbnail. This is where perceived value is built.
7. **Who it's for / who it isn't.** Two columns. Qualifies the buyer and raises conviction.
8. **Proof (REAL only).** Testimonials with attribution, chat-style screenshots, ratings — ONLY if the user supplies them. Otherwise a placeholder block the user fills; never stock faces presented as customers.
9. **Offer stack + price reveal.** List everything included with an honest "value" line, then the real price, then the CTA. One-time payment framing, bonuses, gifts.
10. **Guarantee.** The real guarantee, stated plainly, with the badge. Risk reversal.
11. **Urgency (HONEST only).** A real launch deadline or a real cap. If there is no real scarcity, use value-anchored urgency ("the launch price goes up after launch") without fake live counters. See integrity rules.
12. **FAQ.** 5–8 real objections answered, last one about the refund.
13. **Final CTA + price recap.** Repeat the offer and button.
14. **Footer + legal disclaimer.** Copyright, the "not affiliated with Meta/Facebook" line, privacy/terms/refund links.
15. **Exit-intent popup (optional).** Restates the offer once. Honest framing only.

CTAs repeat about every 1.5 screens on a long page (the peptides page has 8). All primary CTAs point to the SAME next step (checkout). The copy of each CTA varies ("Get instant access", "I want this offer", "Get X for $Y").

## Psychological triggers worth copying (used by the references)

- **Specific, outcome-first headline** with a time frame ("your first protocol built tonight").
- **Mechanism naming** — give the method/app a branded name so it feels like a system, not a file.
- **Value stacking** before the price, then a one-time price that feels small vs. the stack.
- **Risk reversal** — a concrete, conditional guarantee ("if you haven't done X in N days, 100% back").
- **Two-options / who-it's-for** qualification.
- **Objection-handling FAQ** ending on the refund.
- **CTA repetition** with varied labels, all to one checkout.
- **Announcement bar + exit popup** to recover attention.
- **Mobile-first**: the real traffic is mobile; design for a phone first.

## Triggers to use ONLY when real (integrity rules — non-negotiable)

These are the deceptive parts of the reference page. The skill may build the COMPONENT, but only wired to true data the user confirms:

- **Countdown timer** → only for a real deadline (a launch that truly ends, a cart that truly closes). Never a per-visitor timer that resets on reload.
- **Stock / "live purchase" popups ("María just bought", "12 left")** → only with real order data. Default: OFF. Never fabricate names, counts or "X of 200 left".
- **Testimonials / ratings / "4.9 (847 reviews)"** → only real, user-supplied, attributable. Never stock-photo faces (e.g. randomuser.me) or invented review counts.
- **Prices, savings, "value $224"** → the real numbers from the user's checkout. If a figure isn't verified, it isn't shown.
- **Medical / income / results claims** → follow the niche compliance rules; keep the legal disclaimer.

When the user supplies none of the above, the skill inserts a clearly-labeled `<!-- PLACEHOLDER: add real testimonials here -->` block and lists it in the final report as "needs real proof before publishing". A page that fabricates proof gets the business banned from the ad platform and is the opposite of what a scaling offer needs long-term.

## What to pull from the ADS (Ad Library) into the page

The ads that drive traffic set the reader's expectation; the page must match them (message match):
- The **hook / primary text** of the top ads → the hero headline and §4 pain language.
- The **angle** that is being scaled (which pain, which promise) → the page's lead.
- The **offer framing** (price, bonus, guarantee) seen in the ads → keep consistent on the page.
- The **visual style** of the top image ads → the look of the page's hero/mockup images.
Use the Winning Offer Spy's method of counting (page-level active-ad count) to know which ad is actually scaling, and model that one.
